### 자동 갱신 켜기 (서버 없이 깃허브만으로)

깃허브 Actions가 매일 한국 시간 06:17쯤 API를 호출해 `data/bulk-trend.json`을 고쳐 커밋하고 깃허브 페이지 재게시를 요청합니다. 인증키는 깃허브 Secrets에만 있고 홈페이지 파일에는 들어가지 않습니다.

1. 저장소 Settings > Secrets and variables > Actions > New repository secret: 이름 `DATA_GO_KR_KEY`, 값 = 공공데이터포털 일반 인증키
2. Actions 탭 > "울산항 공공데이터 갱신" > Run workflow 로 한 번 실행(로그에 "벌크 화물 동향: 갱신"). 같은 날 이미 갱신했으면 "오늘은 이미 갱신됨"으로 넘어갑니다. 이후 매일 자동
- 호출이 실패하면 기존 파일을 그대로 두어 직전 값이 보입니다.
- `.github` 폴더는 숨김 폴더라 끌어 놓기에서 빠질 수 있습니다. 저장소에 안 보이면 Add file > Create new file 에서 `.github/workflows/upa-data.yml` 이름으로 만들고 내용을 붙여 넣으세요.
- Actions가 올린 커밋은 깃허브 페이지를 자동으로 다시 게시하지 않아서, 작업 마지막에 "깃허브 페이지 다시 게시" 요청을 넣었습니다(Settings > Pages 가 "Deploy from a branch"일 때).

## 깃허브에 버전업하는 방법

### 방법 1. 웹 화면에서 올리기 (가장 쉬움)

1. 기존 저장소 첫 화면에서 **Add file > Upload files** 를 누릅니다.
2. 압축을 푼 폴더 **안의 내용 전체**(index.html, assets·data·scripts 폴더, .github 폴더, 404.html, robots.txt)를 끌어다 놓습니다. 같은 이름의 파일은 새 파일로 덮어써집니다.
3. 아래 Commit changes 칸에 `v3.25 움직임 정리` 처럼 적고 **Commit changes** 를 누릅니다.
4. 1~2분 뒤 기존 주소(https://계정명.github.io/저장소명/)에서 새 버전이 보입니다. 안 보이면 브라우저에서 강력 새로고침(Ctrl+Shift+R)을 해 주세요.

참고: `.nojekyll` 처럼 점(.)으로 시작하는 파일은 끌어다 놓기로 올라가지 않을 수 있습니다. 처음 게시할 때 이미 올렸다면 그대로 두면 되고, 없다면 **Add file > Create new file** 에서 이름을 `.nojekyll` 로 적고 내용 없이 커밋하면 됩니다.

### 방법 2. git 명령으로 올리기

```
git clone https://github.com/계정명/저장소명.git
cd 저장소명
(압축을 푼 폴더 안의 파일을 전부 여기로 복사해 덮어쓰기)
git add -A
git commit -m "v3.25 움직임 정리"
git push
```

### 처음 게시하는 경우

저장소를 공개(Public)로 만들고 위 방법으로 파일을 올린 뒤, **Settings > Pages > Build and deployment** 에서 Source는 `Deploy from a branch`, Branch는 `main` / `(root)` 로 저장합니다.
